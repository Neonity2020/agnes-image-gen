第 7 章：渲染对话与媒体结果

目标：根据同一种 ConversationEntry 渲染文本、图片、视频、加载和失败状态，并给每种结果提供恰当的后续操作。

1. 先渲染用户输入，再渲染模型结果

每个条目始终先显示用户的 prompt，然后才是模型状态或结果。这样即使请求失败，用户也知道哪个创作意图没有完成；也能在长线程中快速定位上下文。

{entries.map((entry) => (
  <div key={entry.id}>
    <UserBubble prompt={entry.prompt} />
    <Result entry={entry} />
  </div>
))}

条目 id 是稳定 key。不要用数组下标，否则并发任务完成、删除或重新排序时 React 可能把错误的 DOM 复用给另一条消息。

2. 状态与媒体类型是两个维度

先按 loading / error / success 分支，再只在 success 下按 text / image / video 分支。这样 loading 和 error 不需要为每种模式复制一套组件。

if (entry.status === "loading") return <LoadingCard mode={entry.mode} />
if (entry.status === "error") return <ErrorCard message={entry.error} />
if (entry.text) return <MarkdownResult text={entry.text} />
if (entry.mode === "image") return <ImageResult url={entry.mediaUrl!} />
return <VideoResult url={entry.mediaUrl!} />

真实项目将这些 JSX 放在一个小组件内以减少抽象层，但分支顺序相同。

3. 文本结果需要安全、可用的 Markdown

使用 react-markdown 与 remark-gfm 渲染列表、表格和代码块。对模型产生的外链，强制加 target="_blank" 与 rel="noopener noreferrer"。长表格必须放进可横向滚动的容器，避免撑破移动端布局。

<ReactMarkdown
  remarkPlugins={[remarkGfm]}
  components={{
    a: ({ children, ...props }) => <a {...props} target="_blank" rel="noopener noreferrer">{children}</a>,
    table: ({ children }) => <div className="markdown-table-wrap"><table>{children}</table></div>,
  }}
>{entry.text}</ReactMarkdown>

复制按钮调用 navigator.clipboard.writeText(entry.text)，复制的是原始 Markdown，而不是渲染后的 DOM 文本，方便用户继续编辑。

4. 图片与视频的最小完整体验

图片使用 <img>，将提示词作为 alt，并用 object-contain 保持比例。成功图片有两个自然动作：下载原始 URL，以及把 URL 回传给父级作为下一次图生图的参考图。

<img src={entry.mediaUrl} alt={entry.prompt} />
<a href={entry.mediaUrl} download={`agnes-image-${entry.created}.png`}>下载</a>
<button onClick={() => onEditImage(entry.mediaUrl!)}>编辑此图</button>

视频优先使用原生 <video controls playsInline>，以获得浏览器的播放、暂停和全屏行为。媒体 URL 来自 entry；渲染组件不需要知道 URL 是即时返回还是轮询得到的。

5. 无障碍与等待体验

会话容器设置 aria-live="polite"，使屏幕阅读器在新结果到来时可获知更新。loading 文案应区分文本、图片和视频的预期时间；例如视频可能需要数分钟，不能复用“正在组织文字”。同时提供 prefers-reduced-motion 样式，避免动画影响需要减少动态效果的用户。

不要只用颜色表达错误或加载。错误卡要有文本标题和具体信息；按钮要有可读名称，而不是只放图标。

动手练习

  1. 为三种 status 建立假数据，在不请求模型的情况下完整渲染。
  2. 让文本返回包含标题、表格、代码块和外部链接的 Markdown。
  3. 给图片增加下载与“作为参考图”按钮，并验证点击后编辑器进入图像模式。
  4. 在窄屏视口测试长表格、超宽图片与视频控件。

自检：若一条任务失败，页面是否仍能显示它的 prompt、模式和错误？如果不能，说明错误状态被设计成了“没有数据”，而不是结果的一种状态。

第 6 章：用 LangGraph 编排多模态 Agent

目标：将“文本、图片、视频该调用哪个函数”的分支，变成一张可视化、可扩展的状态图。

1. Agent 在本项目中不是聊天 UI

这里的 Agent 是一个任务编排模块，不是另一个 React 组件，也不是让模型自主决定工具的黑盒。它接收已经由 UI 确定的 mode，在图中将任务路由至正确的 Agnes 调用函数。这样 React 只需调用一个稳定入口：runAgnesAgent(input)。

2. 先定义状态，而不是节点

图中的每个节点通过共享状态读写数据。项目用 LangGraph 的 Annotation.Root 声明输入和输出：

const AgentState = Annotation.Root({
  prompt: Annotation<string>(),
  mode: Annotation<GenerationMode>(),
  apiKey: Annotation<string>(),
  size: Annotation<string>(),
  referenceImage: Annotation<string | undefined>(),
  history: Annotation<ChatMessage[]>(),
  text: Annotation<string | undefined>(),
  mediaUrl: Annotation<string | undefined>(),
})

前六项是调用方提供的输入；text 与 mediaUrl 是节点产生的输出。状态字段要少且有明确归属，避免把 React 的临时 UI 状态（如弹窗是否打开）混进 Agent。

3. 节点只做一次模型调用

const graph = new StateGraph(AgentState)
  .addNode("route", async () => ({}))
  .addNode("write", async (state) => ({
    text: await generateText(state.prompt, state.apiKey, state.history),
  }))
  .addNode("draw", async (state) => ({
    mediaUrl: await generateImage(state.prompt, state.size, state.apiKey, state.referenceImage),
  }))
  .addNode("animate", async (state) => ({
    mediaUrl: await generateVideo(state.prompt, state.size, state.apiKey),
  }))

节点返回的是状态补丁，而不是直接修改外部变量。这让一次执行的输入输出可观察，也使后续加日志、重试、审核节点更自然。

4. 用条件边表达路由规则

.addEdge(START, "route")
.addConditionalEdges("route", (state) => state.mode, {
  text: "write", image: "draw", video: "animate",
})
.addEdge("write", END)
.addEdge("draw", END)
.addEdge("animate", END)
.compile()

路由函数只返回 mode。这比在 App 写一串 if/else 的收益是：流程图、节点名和边清楚说明了所有合法路径；新增模式时会迫使你同时补上节点和路由。

5. 提供一个小而稳定的调用接口

export function runAgnesAgent(input: AgentInput) {
  return graph.invoke({ ...input, history: input.history ?? [] })
}

调用者不需要知道节点名、边或 LangGraph 状态类型。它只提供提示词、模式、Key、尺寸、可选参考图和历史，再接收文本或媒体 URL。这是本章最重要的模块接口。

不要在 Agent 图中保存全局会话。会话属于浏览器应用状态；本次调用所需的历史由 App 显式传入。这样每个图执行互不污染，也支持并发任务。

动手练习

  1. 安装 @langchain/langgraph，按本章创建三分支图。
  2. 先用返回固定字符串的假 generateText/generateImage/generateVideo 验证路由。
  3. 为每种 mode 调用一次 runAgnesAgent，检查只执行了对应节点。
  4. 新增一个 audio 模式；写下必须改动的状态、节点、条件边和 UI 位置。

自检：如果某个节点需要读取 DOM 或调用 setState，它放错层了；节点应只依赖图状态和 API 适配函数。

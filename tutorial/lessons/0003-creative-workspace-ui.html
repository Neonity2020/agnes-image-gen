第 3 章：搭建创作工作台界面

目标：将空白 React 页面变成一个有明确层次的创作工作台，并让每个 UI 模块只负责一种用户可见的工作。

1. 先划分页面，而不是先写样式

目标应用只有三块长期存在的区域：左侧历史导航、可滚动的创作工作区、固定在底部的提示词编辑器。App 负责把它们排成布局并传入状态；每个区域的内部视觉与交互留在自己的组件文件。

<div className="grid h-dvh grid-cols-1 md:grid-cols-[272px_1fr]">
  <AppSidebar ... />
  <main className="relative flex min-h-0 min-w-0 flex-col">
    <header>...</header>
    <section className="min-h-0 flex-1 overflow-y-auto">...</section>
    <PromptComposer ... />
  </main>
</div>

这里的 min-h-0 很重要：在 flex/grid 子项中，它允许中间区域缩小并由自己滚动，避免长对话把整个页面顶出视口。

2. 用状态驱动“空页”与“对话页”

工作区不应维护一套独立的显示状态。它只根据当前线程的 entries 选择两个组件：

{entries.length === 0
  ? <WelcomePanel suggestions={suggestions} onSelect={selectSuggestion} />
  : <Conversation entries={entries} onEditImage={selectEditImage} />}

WelcomePanel 只负责把预设提示词回传给父级；Conversation 只渲染已有条目。这让“是否存在对话”只有一个事实来源。

3. 组件接口要表达意图，而不是泄露父级状态

以侧栏为例，它接收 conversations 来展示列表，却不直接修改会话数组；它通过 onNewChat、onSelectConversation、onDeleteConversation 表达用户意图。父级 App 决定状态如何变化和如何持久化。

这不是“所有状态都塞进 App”的教条。这里状态确实被侧栏、会话区、编辑器共同使用，放在它们最近的共同父级能避免多个副本失去同步。

4. 复用 shadcn/ui 原语

将按钮、输入框、选择器、弹窗、滚动区域放在 src/components/ui。业务组件组合这些原语，不重复处理基础样式、焦点环或键盘交互：

  • Button：发送、下载、删除与图生图操作。
  • Select：图像/视频尺寸选择。
  • Dialog：API Key 设置。
  • ScrollArea：侧栏中的会话列表。
  • ContextMenu：对话删除入口。

先完成语义正确的 HTML 和可访问名称（例如 aria-label="发送给 Agnes"），再调整颜色、圆角和阴影。视觉相同但无法键盘操作的组件不算完成。

5. 构建提示词编辑器的四类输入

PromptComposer 是受控组件：提示词、模式、尺寸和参考图都从父级传入，并用回调更新。它包含四个独立责任：

  1. 多行提示词：Enter 提交，Shift + Enter 换行，并避开中文输入法组合事件。
  2. 模式切换：文本、图片、视频共享一处选择器。
  3. 尺寸选择：仅媒体模式显示。
  4. 参考图：只在图片模式显示，限制 PNG/JPEG/WebP 和 10 MB，并在浏览器中读为 Data URL。
if (event.key === "Enter" && !event.shiftKey && !event.nativeEvent.isComposing) {
  event.preventDefault()
  event.currentTarget.form?.requestSubmit()
}

6. 为所有结果状态设计界面

Conversation 不是只渲染“成功内容”。每个 ConversationEntry 都可能处于 loading、success 或 error。先把这三种状态画全，再分别处理文本、图片和视频的成功结果。这样用户能在慢速视频生成期间得到明确反馈，而不是面对空白区域。

文本用 react-markdown 与 GFM 插件渲染；图片提供下载与“编辑此图”；视频使用原生 <video controls>。媒体 URL 和提示词都来自同一个条目，展示层无需知道 API 响应细节。

动手练习

  1. 按本章布局建立 AppSidebar、WelcomePanel、Conversation 和 PromptComposer 四个空组件。
  2. 在 App 中用一个 entries 数组切换欢迎页与会话页。
  3. 把编辑器固定在底部，让中间区域在 20 条假消息时独立滚动。
  4. 为发送按钮、上传参考图按钮和侧栏关闭按钮加入可读的 aria-label。

自检：如果长消息使底部编辑器被推出窗口，先检查中间滚动区和它的父级是否使用了 min-h-0。

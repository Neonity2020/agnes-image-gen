第 4 章：设计生成任务与表单交互

目标：把编辑器输入转成可靠的异步任务，并在请求前、请求中和结束后始终给用户正确反馈。

1. 用领域类型描述任务

先定义三种能力与一条可渲染结果记录：

type GenerationMode = "text" | "image" | "video"
type ConversationEntry = { id: string; prompt: string; mode: GenerationMode; created: number; size?: string; text?: string; mediaUrl?: string; status: "loading" | "success" | "error"; error?: string }

status 是任务生命周期的唯一状态字段。不要再维护容易互相矛盾的 isLoading、hasError 和 hasResult。

2. 提交前做三层验证

  1. 内容：prompt.trim() 为空时直接返回。
  2. 资源：没有 API Key 时打开设置弹窗，不发无效请求。
  3. 容量：当 activeTaskCount 达到 MAX_CONCURRENT_TASKS 时拒绝新任务并提示。
const cleanPrompt = prompt.trim()
if (!cleanPrompt) return
if (activeTaskCount >= MAX_CONCURRENT_TASKS) return toast.info("任务已达上限")
if (!apiKey) { setSettingsOpen(true); return }

禁用发送按钮只能改善体验，不能替代提交处理函数中的验证；键盘提交和未来的新入口都可能绕过按钮。

3. 先显示 pending，再等待模型

验证通过后立刻创建 loading 条目。用户马上能看到自己的提示词和处理状态，而不必等待 API 返回。

const id = crypto.randomUUID()
const pending: ConversationEntry = { id, prompt: cleanPrompt, mode, created: Date.now(), status: "loading", size: mode === "text" ? undefined : size }
setEntries((current) => [...current, pending])

真实项目更新的是嵌套的 conversations；这里的关键顺序不变：写 pending、清空编辑器、增加任务数，最后才请求模型。

4. 把参考图当作受限数据转换

图生图不能直接把浏览器 File 塞进 JSON。先验证 PNG/JPEG/WebP 类型和 10 MB 大小限制，再用 FileReader.readAsDataURL 转为 Data URL：

if (!REFERENCE_IMAGE_TYPES.has(file.type)) return toast.error("请选择 PNG、JPEG 或 WebP 图片")
if (file.size > 10 * 1024 * 1024) return toast.error("参考图不能超过 10 MB")
const reader = new FileReader()
reader.onload = () => onReferenceImageChange(reader.result as string)
reader.readAsDataURL(file)

提交时先把参考图存到局部变量，再清除编辑器中的参考图状态；下一次生成不会意外复用它。

5. 异步回写必须能精确定位

用户可以在视频生成期间切换线程。完成处理不能依赖“当前显示的会话”，而必须捕获提交时的 conversationId 和条目 id：

setConversations((current) => current.map((conversation) =>
  conversation.id === conversationId ? { ...conversation,
    entries: conversation.entries.map((entry) =>
      entry.id === id ? { ...entry, status: "success", mediaUrl: result.mediaUrl } : entry) }
  : conversation,
))

失败路径用同样方式写入 status: "error" 和标准化错误。无论成败，finally 都要递减任务数并把焦点放回编辑器。

动手练习

  1. 为表单增加文本、图片、视频三种模式和尺寸选择器。
  2. 用延迟一秒的假 Promise 实现 loading → success 与 loading → error。
  3. 同时提交两条任务，再切换线程，验证各自回写到正确条目。
  4. 上传 11 MB 文件和错误类型文件，确认请求不会发出。

自检：如果失败后发送按钮一直禁用，检查递减 activeTaskCount 的代码是否放在 finally。

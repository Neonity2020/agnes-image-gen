第 2 章：初始化 Vite + React + TypeScript 工程

目标：从空目录创建一个能通过类型检查和生产构建的前端基座，并使它具备与目标应用相同的模块边界和 @/ 导入方式。

1. 为什么从 Vite 的 React TypeScript 模板开始

目标项目是一个静态浏览器应用：开发时需要快速热更新，发布时需要把资源打包为静态文件。Vite 正好提供开发服务器与生产构建两个部分；React TypeScript 模板则让 JSX、类型检查和组件入口从第一天就可用。

pnpm create vite@latest agnes-clone --template react-ts
cd agnes-clone
pnpm install
pnpm dev

本仓库要求 Node.js >=20.19.0 || >=22.12.0。先检查 node --version；版本不匹配时不要急着解决依赖错误，先升级 Node。

2. 先建立会长期稳定的目录

src/
├── components/   # 纯展示与交互组件
├── lib/          # Agent、HTTP、localStorage 等非 UI 行为
├── App.tsx       # 应用协调者
├── main.tsx      # React 入口
├── index.css     # 全局样式与 Tailwind 入口
└── types.ts      # 跨模块共享的领域类型

这里的关键规则是：组件不直接知道 Agnes API 的 URL 或返回格式，lib 也不渲染 JSX。这个小约束会让第 5、6、8 章的扩展集中在少数文件中。

3. 配置 Tailwind v4 与 React

安装目标项目所需的构建依赖：

pnpm add react react-dom
pnpm add -D vite typescript @vitejs/plugin-react tailwindcss @tailwindcss/vite @types/react @types/react-dom

随后在 vite.config.ts 注册 React 与 Tailwind 插件。项目中使用 ESM，因此通过 fileURLToPath(import.meta.url) 取得配置文件所在目录，再计算稳定的绝对路径。

import path from "node:path"
import { fileURLToPath } from "node:url"
import tailwindcss from "@tailwindcss/vite"
import react from "@vitejs/plugin-react"
import { defineConfig } from "vite"

const rootDir = path.dirname(fileURLToPath(import.meta.url))

export default defineConfig({
  plugins: [react(), tailwindcss()],
  resolve: { alias: { "@": path.resolve(rootDir, "src") } },
})

4. 让 TypeScript 也认识 @/

只配置 Vite alias 还不够：编辑器与 tsc 还会把 @/components/button 当成未知模块。把相同映射写进 tsconfig.app.json，并保持严格模式：

{
  "compilerOptions": {
    "strict": true,
    "moduleResolution": "Bundler",
    "jsx": "react-jsx",
    "paths": { "@/*": ["./src/*"] }
  },
  "include": ["src"]
}

路径别名是开发体验工具，不是架构。它的价值是让导入路径表达“从应用根开始”，而不是用一串 ../../ 暗示文件距离。

5. 写下最小可验证入口

src/main.tsx 只负责挂载，App.tsx 只负责输出一个占位页面。先确认工程健康，再加入 AI 功能。

// src/main.tsx
import { StrictMode } from "react"
import { createRoot } from "react-dom/client"
import App from "@/App"
import "@/index.css"

createRoot(document.getElementById("root")!).render(
  <StrictMode><App /></StrictMode>,
)
// src/App.tsx
export default function App() {
  return <main>Agnes Clone</main>
}

6. 质量门：在 UI 之前执行

pnpm typecheck
pnpm build
pnpm preview
  • typecheck 应只运行 TypeScript 项目检查，不生成文件。
  • build 应先检查类型，再生成 dist/。
  • preview 用构建后的产物做本地验收，而非重新启动开发服务器。

动手练习

  1. 新建一个 agnes-clone 目录，完成上述初始化。
  2. 创建 src/lib/example.ts，导出一个字符串常量。
  3. 从 App.tsx 用 @/lib/example 导入并渲染该常量。
  4. 执行 pnpm typecheck && pnpm build。

自检：若 Vite 能启动但 typecheck 报无法解析 @/，你漏配的是 tsconfig.app.json，而不是 vite.config.ts。

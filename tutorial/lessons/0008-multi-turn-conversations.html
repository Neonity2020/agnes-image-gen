第 8 章：实现多轮对话与线程管理

目标：让用户在同一线程中连续提问并获得上下文相关回答，同时可以新建、切换、删除和恢复不同会话，且并发生成不会串线。

1. 为什么“生成历史数组”不够

把每一次生成单独放入 GenerationRecord[]，侧栏点击时只能恢复一条记录，模型也无法知道它前面的问答。多轮功能需要把“会话”提升为一等领域对象：

type Conversation = {
  id: string
  title: string
  created: number
  updated: number
  entries: ConversationEntry[]
}

ConversationEntry 仍然是第 4、7 章中的单次任务；Conversation 负责把它们按线程组织。标题使用首条提示词的截断文本，updated 供侧栏排序。

2. 只有一个活动线程

App 维护完整的 conversations 和可空的 activeConversationId：

const [conversations, setConversations] = useState(readConversations)
const [activeConversationId, setActiveConversationId] = useState<string | null>(null)
const activeConversation = conversations.find((item) => item.id === activeConversationId)
const entries = activeConversation?.entries ?? []

会话区只接收 entries。点击侧栏只改变 ID；它不复制 entries，也不重新组织 history。点击“新的创作”将活动 ID 设为 null，不会删除以前的对话；第一次发送时才真正创建新线程。

3. 从当前线程提取模型上下文

文本模型需要 user/assistant 交替消息，但界面条目同时包含图片、视频、失败和加载状态。提交时只从当前条目中选取成功的文本结果，并限制最近 10 轮：

const history: ChatMessage[] = entries
  .filter((entry) => entry.status === "success" && entry.mode === "text" && entry.text)
  .slice(-10)
  .flatMap((entry) => [
    { role: "user" as const, content: entry.prompt },
    { role: "assistant" as const, content: entry.text! },
  ])

这刻意排除了图片、视频和失败任务。它们仍在视觉会话中，却没有满足文本聊天协议所需的 assistant 回复格式。

4. 首条消息创建线程，后续消息追加

发送时先固定线程 ID。没有活动线程就生成一个；有则复用。接着将 pending 条目追加，并把最新活动线程移到数组开头：

const conversationId = activeConversationId ?? crypto.randomUUID()
const existing = current.find((item) => item.id === conversationId)
if (!existing) {
  return [{ id: conversationId, title: cleanPrompt.slice(0, 48),
    created, updated: created, entries: [pending] }, ...current]
}
const updated = { ...existing, updated: created, entries: [...existing.entries, pending] }
return [updated, ...current.filter((item) => item.id !== conversationId)]

5. 并发时必须按两个 ID 回写

这是多线程最容易出错的位置。任务请求开始后，用户可能切到别的对话甚至新建一条。完成处理绝不能读取那时的 activeConversationId；它应闭包捕获提交时的 conversationId，再在该线程中用 entry.id 找到占位条目。

setConversations((current) => current.map((conversation) =>
  conversation.id === conversationId ? {
    ...conversation, updated: Date.now(),
    entries: conversation.entries.map((entry) =>
      entry.id === id ? { ...entry, status: "success", text: result.text } : entry),
  } : conversation,
))

失败路径必须使用完全相同的定位规则。若只在成功时正确回写，网络异常时就会污染当前线程或留下永久 loading 条目。

6. 侧栏与线程操作

侧栏显示一个 Conversation[]，标题来自 conversation.title，时间来自 conversation.updated。选择会话只执行 setActiveConversationId(id)；删除会话从数组过滤它，如果删除的是当前线程，则选择下一个线程或回到空状态。不要将“删除侧栏项”实现为删除某一条 entry。

动手练习

  1. 将旧的扁平历史改为 Conversation[]，实现空状态、新建、选择与删除。
  2. 连续完成三轮文本问答，检查第三次 API 请求携带前两轮 user/assistant 消息。
  3. 在 A 线程发起慢任务，立即切到 B 线程发起另一任务；确认两个结果分别回写。
  4. 在线程中插入一次图片生成，验证下一次文本请求不包含图片条目。

自检：如果切换侧栏后模型继续引用上一条线程，检查 history 是否从 entries（当前活动线程）构造，而不是从所有 conversations 扁平化构造。
